# 접근성 추출 작업 지시 (각 청크 파일 1개 담당)

입력: JSON 배열. 각 항목 = 장소 {id, name, cat, unit, addr, docs:[{u,d,t}]}
- docs[].t 는 블로그 글의 "제목 | 본문 앞부분 스니펫" (최대 280자). 글 전체가 아님.

할 일: 각 장소마다, 스니펫에 쓰여 있는 사실만으로 **그 장소의** 휠체어 접근성을 판정한다.

## 절대 규칙
1. 스니펫에 없는 내용은 추정 금지. 모르면 null / "미확인".
2. 스니펫이 여러 장소를 나열하는 글이라 접근성 문구가 **이 장소에 대한 것인지 확실하지 않으면** relevant=false, verdict="미확인".
3. quote 는 스니펫 원문에서 **글자 그대로 복사**한 40자 이내 구절 (판정 근거). 없으면 null. 요약·수정 금지.
4. summary 는 원문을 베끼지 말고 30~60자 한국어 요약 (예: "입구 경사로, 장애인 화장실 있음").
5. 업체 정보란식 표기("휠체어 이용 가능" 아이콘/편의시설 목록 복붙)는 source="표기", 실제 다녀온 서술("휠체어 밀고 들어갔는데…")은 "방문", 관광공사·열린관광·공식 안내 인용은 "공식안내".
6. "불가"는 실제로 못 들어갔다/계단만 있다/엘리베이터 없어 올라갈 수 없다 등 이 장소에 대한 명확한 서술이 있을 때만.
7. 광고로 보이는 글(체험단 흔적, 과한 홍보)은 ad=true 로 표시(판정은 그대로 하되 참고).

## 출력: 같은 폴더에 result_<입력파일이름에서 chunk_ 뺀 것>.json 으로 저장 (JSON 배열, 입력 순서 유지, 모든 id 포함)
각 항목:
{"id":"...","relevant":true,"verdict":"가능|부분|불가|미확인","source":"방문|표기|방문+표기|공식안내|null",
 "summary":"...","caution":"주의사항 or null","elevator":"있음|없음|null","toilet":"있음|없음|null",
 "parking":"있음|null","stroller":"가능|어려움|null","quote":"원문 그대로 or null","doc":"근거로 쓴 docs[].u","ad":false}

판정 기준: 가능 = 휠체어로 진입·이용 가능하다는 서술(경사로, 턱 없음, 엘리베이터, 장애인화장실, 휠체어 대여 등)이 이 장소에 대해 있음.
부분 = 가능한 부분과 제약(일부 계단, 가파른 경사, 2층 화장실 등)이 함께 있음. 불가 = 위 6번. 미확인 = 나머지.

작업 방식: 파일을 Read 로 끝까지 읽고(필요하면 나눠 읽기), 판단한 뒤 python 으로 결과 JSON 을 저장하라. 저장 후 python 으로 json.load 해서 개수가 입력과 같은지 확인하라. 마지막 답변은 "파일명, 개수, verdict 분포" 한 줄만.
