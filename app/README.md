# EasyTrip 소스 코드 (수정용 폴더 구조)

무장애 여행 플래너 프로토타입. 원래 2.7MB짜리 HTML 1개였던 것을 **역할별 파일로 분리**했습니다.
동작은 원본과 동일합니다(초기 화면·지역 4곳 전환 후 화면 HTML이 글자 단위로 일치하는 것을 확인).

## 실행 / 배포
| 하고 싶은 것 | 방법 |
|---|---|
| 바로 열어서 확인 | `index.html` 을 크롬/사파리에서 열기 (서버 불필요) |
| 한 파일로 합치기 | `python3 build.py` → `dist/EasyTrip.html` (공유·업로드용) |

> 인터넷이 연결돼 있으면 글꼴(IBM Plex)·Leaflet을 외부에서 받아옵니다. 없어도 앱은 뜹니다.
> `AI 기능`(후기 분석, AI가 다시 골라줘)은 claude.ai에 올렸을 때만 켜지고, 로컬에서는 데모 결과로 동작합니다.

## 폴더 지도
```
easytrip/
├─ index.html            ← 파일 불러오는 순서(번호 순서 유지!)
├─ build.py              ← 한 파일로 합치는 스크립트
├─ css/style.css         ← 색·글꼴·크기·레이아웃 (디자인 수정은 여기)
├─ data/
│   ├─ regions_real.js   ★ 경주·전주·강릉·서울(강북/강남)·부산 7묶음 실데이터
│   ├─ regions_base.js   ★ 경산 실데이터 (+ 구버전 예시 잔재)
│   └─ images.js         사진·아이콘 base64 (열지 말 것, 파일이 큼)
└─ js/
    ├─ 01_state_config   상태(S), 이동유형, 필터, 제보유형, 연락처
    ├─ 02_shell_markup   화면 HTML 뼈대 (탭·시트·온보딩 문구)
    ├─ 03~06             달력 / AI 추천 동선 / 이동유형 선택
    ├─ 07_region         지역 선택
    ├─ 08_spots          편의 스팟 목록·접근성 근거·데이터 수집 현황 카드
    ├─ 09_reviews        후기   10_reports_me  제보·내 정보
    ├─ 11_sheets_ui      택시·화장실·할인·동행자·SOS·예약 시트
    ├─ 12_geo_map        좌표·지도(구버전)   13_region_photos  지역 사진
    ├─ 14_init / 15_boot 앱 시작
    ├─ 20_ai             AI 기능 (후기 분석, 근거 인용 검증, AI가 다시 골라줘)
    ├─ 30~34             서울/부산 선택 화면·일러스트, SVG 지도, 장소 사진
    └─ 35_type_judg      v9 이동 유형 3종 판정·유형 필터·유형별 동선 (TYPE_JUDG는 tools/merge_types.js가 채움)
```
각 js 파일 맨 위 주석에 그 파일이 하는 일이 적혀 있습니다.

## 자주 하는 수정
- **문구/버튼 이름 바꾸기**: `js/02_shell_markup.js` (화면 문구 대부분), 목록류는 `01_state_config.js`
- **색상·글자 크기**: `css/style.css` 맨 위 `--sky`, `--pri-g` 같은 변수
- **앱 이름 바꾸기**: `index.html`의 `<title>`·`apple-mobile-web-app-title`, `02_shell_markup.js`의 `EasyTrip` 검색해서 교체
- **장소 추가/수정**: 아래 데이터 구조 참고
- **이동유형 아이콘**: `data/images.js`의 `MOB_IMG`

## 지역 데이터 구조 (`regions_real.js`, `regions_base.js`)
```js
gyeongju: {
  name:"경주", sub:"경상북도", en:"Gyeongju", real:1,        // real:1 = 실데이터 → 화장실·할인 버튼 활성
  taxi:{n:"기관명", tel:"번호", note:"...", wait:""},
  days:[ {sub:"황리단길", stops:[ {n:"장소명", k:"식당|카페|숙박|관광명소|문화시설",
      t:"10:00", s:"가능|부분|불가|미확인",
      f:[["휠체어","가능 · 방문 후기","ok"], ["근거","후기에서 뽑은 원문 요약","ok"], ["주의","...","warn"]],
      leg:"직선 0.2km", note:"주의사항"} ]} ],
  toilets:[...], discounts:[...],
  spots:[...],           // 편의 스팟 탭 목록
  dataNote:{...}         // '데이터 수집 현황' 카드 (수집 건수·커버리지)
}
```
- `f` 배열의 세 번째 값: `ok`(초록) · `warn`(주의) · `no`(불가)
- 판정 `s` 는 **후기 원문에 근거 문장이 있을 때만** 채웁니다(근거 인용 검증). 근거 없이 임의로 채우지 마세요.

## 알려진 한계 (수정 시 참고)
- 이동유형 판정은 현재 **휠체어 중심**. 노약자·시각장애 판정(TYPE_JUDG)은 아직 비어 있어 해당 유형을 고르면 '확인된 장소 없음'으로 나옵니다(추정으로 채우지 않음).
- 서울·부산·경주·전주·강릉 데이터는 허브 반경 1.5km 표본입니다(전수 아님).
- 사진은 검색 결과 썸네일(프로토타입용)입니다. 실서비스 전 저작권 확인이 필요합니다.
- 카카오 키는 제거했습니다(`js/12_geo_map.js`의 `KAKAO_KEY`가 비어 있음). 지도는 자체 SVG라 키 없이 동작하며, 데이터 수집기는 별도 파일입니다. 키를 넣더라도 코드에 직접 적어 공유하지 마세요.
